Breaking / behavioural changes found in the window (releases list + docs):
- 3.4.3 -> 3.5.0 changed the PromptEditor newline gesture from Ctrl+N to
  Shift+Enter (Ctrl+N kept as fallback); 3.4.3 itself had just introduced
  Ctrl+N. Key bindings are not frozen yet.
- The hosting docs state that inline/fullscreen loops "now default to
  LoopMode = Auto" and that "UpdateWaitDuration is no longer the default frame
  cadence control" — a behaviour change to the host loop default in the 3.x
  line (documented, not marked as breaking in a changelog).
- API evolution is continuous: e.g. 3.9.0 added configurable scroll bar
  visibility; 3.10.0 changed focus/menu and DataGrid behaviour.
- No migration guide or breaking-change section was found; releases are
  dotnet-releaser generated "Changes" lists. Semver is followed loosely:
  UI-affecting changes arrive in minor bumps, not majors.

Testing infrastructure (make-or-break gate)
-------------------------------------------
Public in XenoAtom.Terminal (all verified from the user guide and the packages):
- `InMemoryTerminalBackend`: capture output (`GetOutText()`) and inject events
  (`PushEvent`, `SetSize(..., raiseEvent: true)`) — scriptable input and output
  capture with no real terminal.
- `Terminal.Open(backend, options, force: true)` opens a session on that backend.
- One-shot rendering: `TerminalInstance.Write(visual)`.
Internal (not public; used by the library's own tests):
- `TerminalApp.BeginRun()`, `TerminalApp.Tick(long timestamp)` (virtual clock),
  `TerminalApp.SetUpdateCallback(...)`, `TerminalApp.EndRun()`, plus the
  `TerminalAppTestDriver` helper class; the library's test project
  `src/XenoAtom.Terminal.UI.Tests` (~170 test classes) drives deterministic ticks
  and an `AnsiTestScreen` parser.
- S-6 proved the internal hooks are reachable through reflection and used them
  for the deterministic tests (TickDriver.cs). The public surface alone cannot
  step frames deterministically.
- Caveat: only one global `TerminalInstance` can be open at a time; opening a
  second session (`force: true`) disposes the first. Snapshot renders must run
  while no other session is live.

Inline/live features relevant to the spike (verified in docs/source)
--------------------------------------------------------------------
- `Terminal.Live(visual, onUpdate)` runs an inline live region; `Terminal.Write`
  writes finished blocks above it (documented and exercised by S-6).
- `TerminalApp` routes input to the focused visual; KeyDown/TextInput are
  Bubble-routed. `TextEditorBase` registers a Ctrl+C copy command that consumes
  the gesture before KeyDown routing (S-6 removes it to honour Lunate's
  Ctrl+C contract).
- `PromptEditor` is the promoted prompt input control; `MarkdownControl`
  (Markdig) lives in the separate Extensions.Markdown package.
- The inline host repaints via a cell-buffer diff (synchronized output mode
  2026); the host loop coalesces invalidations (~15 ms active cadence cap).
