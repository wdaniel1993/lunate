# Provider presets, a generated catalog and priced turns

## Why

Lunate ships four hand-written catalog entries, two hard-coded providers and one key variable
per native provider. Anyone using OpenRouter, DeepSeek, Groq, Google or another OpenAI-compatible
endpoint has to hand-write `~/.lunate/models.json`, invent a provider name the factory does not
know, and put the key in the same `openai` slot. There is no way to see what a turn costs, and no
quick way to flip between the models a person actually uses.

models.dev already publishes the cross-provider model data — context and output limits, pricing,
vision and reasoning flags — that the catalog duplicates by hand. This change makes that data a
generated snapshot, turns the eleven named endpoints into presets with their own key variables,
and puts the resulting price and favourites information in the places people look: the footer and
`/session`.

## What Changes

- **Generated catalog (schema 2).** `src/Lunate.Ai/models.json` becomes a deterministic snapshot of
  models.dev for the preset providers, regenerated by a repo script. Entries gain `pricing`
  (input, output, cache read and cache write per million tokens), `maxOutput`, `supportsVision`
  and an optional `wireId` (the upstream model id when the catalog id is qualified). The loader
  accepts schema 1 and 2; `~/.lunate/models.json` keeps overriding the snapshot by id.
- **Provider presets.** `openai` and `anthropic` stay native; `openrouter`, `deepseek`,
  `moonshotai`, `zai`, `opencode`, `opencode-go`, `groq`, `togetherai`, `xai` and `google` route
  through the OpenAI-compatible adapter with a preset base URL and key variable. Presets live in
  one embedded `providers.json` shared by the runtime, the generator and the docs.
- **Qualified model ids.** Non-native catalog ids read `<provider>/<model>`
  (`openrouter/anthropic/claude-sonnet-5-5`); the four existing ids stay bare, native models stay
  bare, and the upstream id travels in `wireId`.
- **`/login <provider>` and `/logout <provider>`.** Keys are stored through the existing
  owner-only `AuthStore`. `/login` asks for the key in a masked live-area prompt; the secret never
  enters input history, the session file, transcript or notices. The provider environment variable
  and a model's `auth` reference remain the other resolution paths.
- **`lunate --update-catalog`.** Explicitly refreshes `~/.lunate/models.catalog.json` from
  models.dev without touching the user's `models.json` or making a model call. The repo script uses
  the same mapper with an output path, so there is one mapping implementation.
- **Costing.** `ModelInfo` exposes the catalog's pricing and limits. The footer shows the current
  turn's cost when every token lane in that turn is priced; `/session` shows the session total with
  a per-model and per-lane split. Unknown pricing shows tokens only, never `$0`.
- **Favourites.** `settings.json` carries an ordered `favorites` list (at most eight). `Ctrl+P`
  cycles through it, `/favorite` and `/unfavorite` edit it, and the footer shows the current
  position.
- **Session usage lanes.** Session message usage gains optional cache-read and cache-write counts
  (schema 3, additive) so a replayed session can be costed exactly. Existing schema 1 and 2 files
  and their goldens stay valid.
- **Documentation and ADR.** README and the guide describe presets, login, the catalog update and
  cost display; ADR-0022 records the catalog source, pricing and auth decisions.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `ai-layer`: generated schema-2 catalog, provider presets and routing, qualified ids, pricing and
  capability fields, credential precedence.
- `agent-config`: preset key variables, `/login` and `/logout`, `--update-catalog`, settings
  schema 2 with favourites, discovery through presets.
- `agent-sessions`: schema 3 usage lanes and the `/session` cost report.
- `tui`: masked login prompt, footer cost and favourite position, `Ctrl+P`, the new commands.
- `print-mode`: `costUsd` in `--json` `usage_updated` when the turn is fully priced.

## Impact

- **Code**: `src/Lunate.Ai` (catalog, presets, mapping, pricing, factory), `src/Lunate.Agent`
  (session usage lanes), `src/Lunate.Coding` (settings/auth writers, commands, catalog update,
  cost aggregation), `src/Lunate.Tui` (footer, key router, secret prompt).
- **Data**: `src/Lunate.Ai/models.json` and `providers.json`; new optional
  `~/.lunate/models.catalog.json`; `settings.json` schema 2; `auth.json` gains preset keys;
  session schema 3 for new files.
- **Public API**: `ModelInfo` init properties, `ModelPricing`, `ProviderPreset(s)`, a cost helper,
  `SessionUsage` cache fields and footer model fields; all recorded in `PublicAPI.Unshipped.txt`.
- **Compatibility**: schema 1 model catalogs, settings and sessions still load and keep their
  bytes; the four existing bare model ids keep resolving.
- **Non-goals**: subscription OAuth (Claude Pro/Max, ChatGPT) for any provider, embeddings, audio
  models, a hosted catalog service, automatic background refresh, and tiered/context-length price
  special cases beyond the catalog's base rate.
